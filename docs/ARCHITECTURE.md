# «Запросто» — архитектура и решения

Источник требований: `SPEC.md` (копия в корне репозитория). При сомнениях — перечитать SPEC.md, не додумывать.

## Сценарий
1. Клиент открывает главную: 3D-персонаж выбранной категории + каталог работ с ценами.
2. Выбирает категорию (по умолчанию Мебель / Сантехника / Электрика / Ремонт / Бытовая техника / Другое; владелец меняет список в кабинете), добавляет работы в корзину, меняет количество и параметры (сложные условия, демонтаж старого).
3. Корзина показывает известную сумму, работы с ручной оценкой («По фото»), минимальный заказ, ориентировочное время. Материалы не входят — сказано прямо.
4. Оформление: имя, телефон, адрес, этаж и доступ (подъезд, домофон, лифт, парковка — необязательно), выезд за город, срочный выезд, кто покупает материалы, желаемые дата/время (необязательно; время только вместе с датой), до 3 фото, комментарий, согласие.
5. Сервер заново считает заявку из своего прайса, сохраняет снимок условий, отдаёт приватную ссылку `/o/<токен>`. Повтор с тем же Idempotency-Key возвращает ту же заявку.
6. Владелец в `/admin` видит заявку, звонит, ставит итоговую цену и время, статус «согласована». Клиент видит изменения по той же ссылке.
7. После заявки (если включено) — мини-игра «отмой персонажа»; в режиме «бонус» выдаётся один код на заявку, погашение вручную владельцем.

## Стек (версии проверены 2026-11-19)
- Next.js 16 (App Router, TypeScript), React 19.3, Tailwind CSS 4, `motion` (motion/react) для UI.
- three 0.187 + @react-three/fiber 9 + @react-three/drei 10 (peer: react >=19 <19.4).
- PostgreSQL (любой: локальный, Supabase, Neon) через `postgres` (porsager). На serverless с пулером — `prepare: false`.
- `zod` для проверки входа, `sharp` для фото, `vitest` для модульных и интеграционных тестов, Python Playwright (скилл webapp-testing) для E2E.
- Без платных LLM и внешних сервисов во время работы сайта.

## Хранение данных (одна компания = свой экземпляр и своя база)
- `settings` — одна строка jsonb-разделов: `company`, `pricing`, `game`, `characters`. В `company` — в том числе `orgsEnabled`, `invoiceEnabled`, `orgNote` (работа с организациями; для старых записей без этих полей действуют значения по умолчанию из zod). Прайс работ — таблица `services` (с флагом `office`), категории — таблица `categories` (`id`, `title`, `color`, `character`, `active`, `sort`; `services.category` — внешний ключ).
- `orders` — заявка: контакты, адрес, доступ, заказчик (`client_type` person|organization, `org_name`, `org_inn` — 10 или 12 цифр, `wants_invoice`), флаги, пожелания, `pricing_snapshot` (jsonb, условия на момент отправки), итог владельца, приватная заметка, статус, `public_token_hash` (sha256 от 32-байтного токена), `idempotency_key` (unique).
- `order_events` — история (создана, статус, цена, время, заметка).
- `photos` — bytea (WebP после сжатия), `upload_key_hash`, `order_id` (null до отправки). Отдаются только владельцу через сессию. Непривязанные старше 24 ч удаляются.
- `owner` (одна строка, scrypt-хеш пароля), `sessions` (sha256 id, срок), `rate_limits` (окно/счётчик), `bonus_codes`.
- Миграции — SQL-файлы `db/migrations/*.sql` + `npm run db:migrate`; демо-данные — `npm run db:seed` (всё вымышленное).

## Правила расчёта (один порядок, деньги — целые рубли)
Для каждой позиции с фиксированной ценой (или почасовой):
1. `base = цена_единицы × количество` (почасовая: цена = `pricing.hourRate`).
2. `pct = (сложные ? complexPct : 0) + (демонтаж и работа это допускает ? dismantlePct : 0)` — проценты позиции складываются.
3. `line = round(base × (100 + pct) / 100)` — округление до рубля (половина вверх).

По заказу:
4. `subtotal = Σ line` (только известные позиции).
5. `minimumTopUp = subtotal > 0 && subtotal < minOrder ? minOrder − subtotal : 0` — минимум относится только к работам.
6. `urgent = срочно ? round((subtotal + minimumTopUp) × urgentPct / 100) : 0`.
7. `worksTotal = ceil((subtotal + minimumTopUp + urgent) / 10) × 10` — итог работ вверх до 10 ₽.
8. `outOfTown = за городом ? outOfTownFee : 0` — фиксированно, без процентов и минимума.
9. `knownTotal = worksTotal + outOfTown`.
- Работы «По фото» (категория «Другое» и любые с `pricing = 'manual'`) не имеют цены: показываются отдельно как «оценка по фото», никогда как 0 ₽. Если известных работ нет — показываем только «Стоимость — по фото» (+ выезд за город, если отмечен). Если в заказе есть ручные позиции, доплата до минимума помечается как предварительная.
- Время: `minutes = Σ norm × qty`; показываем вверх до 10 мин («≈ 2 ч 30 мин»), плюс «+ время по фото», если есть ручные позиции. Дорога не учитывается.
- Единицы: `pcs` (шт), `m` (пог. м), `m2` (м² — для небольших площадей: ламинат, обои), `hour` (ч). Шаги: шт — 1; м, м², ч — 0,5; час — минимум 1.
- Одинаковые позиции объединяются по ключу `serviceId + complex + dismantle` (количество суммируется). «Другое» не объединяется никогда.
- Сервер не доверяет сумме браузера: клиент шлёт только `serviceId`, `qty`, флаги, описание; сервер берёт цены из БД, считает той же чистой функцией `src/lib/pricing.ts` и сохраняет снимок.

## Безопасность
- Владелец: пароль (scrypt), сессия в httpOnly cookie (SameSite=Lax, Secure в production), id сессии хранится как sha256. Смена пароля удаляет все сеансы. Вход ограничен по частоте.
- Все изменяющие запросы: проверка Origin (совпадает с `APP_ORIGIN` или Host). Админские мутации — Server Actions с проверкой сессии в каждой.
- Ограничения частоты в Postgres (работает на serverless): вход, заявки, загрузки фото, бонус.
- Приватные страницы `/o/*`, `/admin/*` и все `/api/*` — `Cache-Control: no-store`, `noindex`, не кешируются service worker.
- Публичный JSON заявки не содержит телефон, адрес, заметку владельца и фото.
- Фото: проверка реального формата через sharp (jpeg/png/webp), лимит входа 12 МБ и 40 Мпикс, на выходе WebP ≤ 1600 px. Клиент заранее уменьшает фото до ~2000 px (лимит тела запроса serverless 4,5 МБ).

## 3D
- Шесть персонажей; категория (строка БД) выбирает одного из них полем `character`: `furniture` — шкаф, `plumbing` — смеситель, `electrics` — лампа, `repair` — валик, `other` — ящик с инструментами, `appliances` — стиральная машина. У исходных категорий id совпадает с ключом персонажа. Подробности про пять первых: Мебель — шкаф; Сантехника — смеситель; Электрика — настольная лампа (у лампы лицо на абажуре выглядит дружелюбно; у розетки гнёзда сами читаются как лицо и легко выходят крипово); Ремонт — малярный валик; Другое — ящик с инструментами.
- Модели доработаны в Blender (`assets-src/blender/zaprosto-characters.blend`), экспорт GLB с клипами `Idle`, `Wave`, `Blink`, оптимизация gltf-transform (meshopt, WebP), декодер meshopt из three (без CDN).
- Персонаж меняется только по категории; выбор конкретной работы меняет тариф, но не модель.
- Постеры PNG/WebP из Blender — для загрузки и для браузеров без WebGL; заказ работает без 3D.

## Что не входит в эту версию (оценивается отдельно)
Онлайн-оплата, расписание мастеров, выбор мастера по району, роли, CRM, уведомления (SMS/мессенджеры/почта), автоматическое погашение бонусов, античит игры.
