# Макеты в Figma

Отдельный редактируемый файл с основными экранами и состояниями приложения «Ладно».

- Файл: **«Ладно — экраны и состояния»**, https://www.figma.com/design/mY1ZJhvcCSTPgWMi3g1UCD
- Ключ файла: `mY1ZJhvcCSTPgWMi3g1UCD`. План: Starter, место View (создание файла и запись в него через MCP работают).
- Состояние на 19.11.2026: клиентские экраны, кабинет и страница «Игра и служебные» (игра, информационные страницы, офлайн) сняты с работающего приложения. Кадры страницы «Игра и служебные» не переименованы и не разложены по рядам: квота Figma MCP кончилась (см. ниже «Квота Figma MCP» и таблицу узлов).

## Как сделаны

Вручную не рисовались: страницы сняты с работающей production-сборки приложения инструментом `generate_figma_design` (MCP Figma). Инструмент превращает DOM в слои Figma: фреймы с автолейаутом, текст, векторы, изображения. Текст остаётся текстом, шрифты Golos Text и Unbounded те же, что в приложении (на странице «Клиент»: около 2 300 фреймов, 1 200 текстовых слоёв, 140 векторов; изображения — только фото и 3D-сцена). Компонентов и переменных дизайн-системы в файле нет: кадры собраны из «сырых» фреймов, это слепок экрана, а не библиотека.

После снятия через `use_figma` только организован файл: кадры названы по-русски, разложены по рядам, над каждым — подпись, лишние служебные узлы убраны, у кадров включено обрезание по границе (так прячется «Перейти к содержимому», которое в браузере видно только при фокусе).

Что подправлено в странице перед снятием (в Figma иначе выходило не так, как в браузере):

- Главная и листы (`dialog`) обрезаны по высоте окна (`html, body { height: 844px; overflow: hidden }`): кадр — это экран, а не вся длинная страница. Остальные страницы сняты на всю высоту.
- Для листов z-index липких элементов (шапка, ряд категорий, нижняя панель корзины) занижен, у открытого `dialog` — максимальный: в Figma нет «верхнего слоя» браузера и без этого панели торчали поверх листа.
- На десктопной главной WebGL-холст заменён снимком (`canvas.screenshot()` → `<img>`): чтение холста при снятии иногда даёт пустую сцену. 3D-сцена в Figma — растровое изображение, остальное редактируемо.

## Как снять заново после изменений

1. Сборка и запуск своего сервера (порт 3105, своя база):

   ```bash
   cd ladno
   NEXT_DIST_DIR=.next-figma npm run build
   git checkout -- tsconfig.json          # сборка правит tsconfig.json
   NEXT_DIST_DIR=.next-figma DATABASE_URL=postgres://hfah:hfah_dev_pw@127.0.0.1:54329/hfah_figma \
     APP_ORIGIN=http://localhost:3105 npx next start -p 3105
   ```

   Под `next start` проверка origin ждёт `http://localhost:3105`, а не `127.0.0.1`: страницы и API открывать по `localhost`.

   База `hfah_figma` — отдельная (миграции + посев). Демо-заявки создают через публичный API (`POST /api/orders`, заголовки `Origin: http://localhost:3105` и `Idempotency-Key: <uuid>`; фото — `POST /api/uploads`), «согласована» ставят SQL-ом в этой же базе (`status='agreed'`, `final_price`, `agreed_at`). Пароль владельца демо — `ladno-demo-2026`.

2. На каждый кадр — свой `captureId`: вызвать `generate_figma_design` с `fileKey` и `nodeId` страницы Figma (`0:1` «Клиент», `1:2` «Кабинет», `1:3` «Игра и служебные»); один и тот же `promptId` на всю серию. Новый кадр появится справа от последнего на этой странице.

3. Открыть нужное состояние в Playwright и отправить снимок. Ловушки, на которых мы споткнулись:

   - контекст браузера с `bypass_csp=True`;
   - **не задавать** контексту свои заголовки (`extra_http_headers`, например `X-Forwarded-For`): запрос к `mcp.figma.com` станет с предзапросом CORS и будет отклонён;
   - `captureForDesign` не завершается сам: не ждать его промис, ждать ответ 200 на `…/submit` и после него ещё секунду-две.

   ```python
   js = urllib.request.urlopen("https://mcp.figma.com/mcp/html-to-design/capture.js").read().decode()
   ctx = browser.new_context(viewport={"width": 390, "height": 844}, color_scheme="light", locale="ru-RU", bypass_csp=True)
   page = ctx.new_page()
   # ... привести страницу в нужное состояние (корзина, форма, лист) ...
   page.add_script_tag(content=js)
   with page.expect_response(lambda r: "mcp.figma.com" in r.url and "/submit" in r.url, timeout=170000):
       page.evaluate("o => { window.figma.captureForDesign(o).catch(() => {}); }", {
           "captureId": CAPTURE_ID,
           "endpoint": f"https://mcp.figma.com/mcp/capture/{CAPTURE_ID}/submit?bindVariables=true&promptId={PROMPT_ID}",
           "selector": "body"})
   page.wait_for_timeout(1500)
   ```

4. Опросить `generate_figma_design` с тем же `captureId`, пока не придёт «The design has been added…» (обычно с первого раза). Один `captureId` — один снимок, повторно использовать нельзя.

5. Старый кадр удалить, новый назвать и поставить на место через `use_figma` (на странице, где он лежит; страницы подгружаются по одной: `await figma.setCurrentPageAsync(page)`). Инструмент оставляет на странице пустой узел «Sticky placeholder – Container» — его удалить.

Селекторы состояний — в `e2e/test_client_flow.py` и `e2e/test_admin_flow.py` (заполнение корзины, формы, вход в кабинет).

## Квота Figma MCP

На плане Starter с местом View действует общий лимит 20 вызовов в месяц. Практика 19.11.2026 показала: в него входят не только чтение (`get_screenshot`, `get_metadata`, `get_design_context`, `get_variable_defs`, `search_design_system`, `get_libraries`), но и **`use_figma`**, хотя запись по описанию должна быть вне лимита. После 3 вызовов `get_screenshot` и 16 успешных вызовов `use_figma` (раскладка, переименование, проверки) следующий `use_figma` вернул ошибку: «You've reached the Figma MCP tool call limit on the Starter plan». Продолжали работать без ограничений: `generate_figma_design`, `create_new_file`, `whoami`. Следствия:

- Весь бюджет `use_figma` нужен на организацию файла: имена, раскладку, чистку. Не тратить его на проверки; для проверки хватает кадра из `generate_figma_design`, а скриншот кадра можно снять самим приложением в Playwright (так мы сверяли состояния до съёмки).
- Сначала снять всё, потом одним-двумя вызовами `use_figma` организовать файл (в одном вызове можно переименовать и разложить десятки кадров, на странице Figma — один `setCurrentPageAsync` за вызов).
- Имя кадра берётся из `document.title` страницы во время съёмки: задать его заранее — и переименование не нужно.

## Известные замечания
